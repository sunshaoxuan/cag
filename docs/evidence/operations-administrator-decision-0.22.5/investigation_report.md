# 0.22.5 管理员决策入口调查

日期：2026-08-03

## 用户问题

问题发生次数从 2 次增加到 100 次后，管理员仍需要明确决定继续修订、批准受控自增益、登记人工处理或禁止本轮修改。入口应位于问题详情顶部，避免被长篇方案、阻断项和日志遮挡。

## 已验证根因

| 结论 | 证据 | 置信度 | 限制 |
|---|---|---|---|
| 发生次数不参与状态动作计算 | `OperationalIssueService._actions_for_status` 只读取状态与 Review 门禁 | 高 | 次数仍用于影响判断和展示 |
| 方案待修订只返回 `reopen` | 0.22.4 生产 API 中 `OI-10CE919F81` 和 `OI-6B26534BF5` 均只有 `reopen` | 高 | 管理员无法结束当前修改方案 |
| 页面动作位于长篇决策摘要之后 | `OperationsCenterPage.tsx` 旧结构先渲染摘要、改进点和阻断项，再渲染操作表单 | 高 | 小屏和长方案更难发现 |
| 后端拒绝仅接受等待审批 | `OperationalIssueService.reject` 的旧状态判断 | 高 | 方案待修订、分诊失败和等待外部处理无法拒绝 |

## 修复决策

1. 在问题标题下方放置唯一的管理员决策区，并在每个状态显示当前可执行动作或等待原因。
2. 明确说明发生次数只表示影响，不改变管理员权限。
3. 审批门禁继续保持独立 Review 通过、零阻断项和 `approval_ready` 三项条件。
4. 方案待修订和分诊失败允许重新调查，也允许管理员结束当前周期并禁止本轮修改。
5. 等待外部处理允许登记实施证据，也允许管理员结束当前周期并禁止本轮修改。
6. 拒绝继续写入认证管理员、原因和 `issue.rejected` 审计事件，保留全部历史。
