# 中文问题归纳补强报告

日期：2026-07-31

版本：0.22.2

## 发现

0.22.1 已经要求管理员审核内容使用简体中文。对
`OI-6B26534BF5` 执行真实重新规划时，模型返回的归纳、根因、改进点和
验收内容均为中文。结构化语言门禁仍将 `proposed_changes.area` 中的纯
文件路径识别为缺少中文，最终生成了中文失败回退摘要。

同一次调查发现重新打开问题时沿用相同的工作区任务标识。工作区管理器对
已经存在的 Git 检出直接复用，因此新的规划可能检查旧版本源码。

## 修正

1. 继续校验问题归纳、影响、根因、目标、实施方式说明、改进内容、原因、
   验收、回滚和管理员操作是否包含中文。
2. `area` 可保留文件路径、命令和代码标识，避免技术证据被语言门禁误判。
3. 每轮规划的工作区标识加入 `issue.triage.started` 事件序号。
4. 重新打开和评估失败后的下一轮规划会克隆当前默认分支。
5. 旧规划工作区继续作为不可变证据保留。

## 验收

同一个问题连续三轮规划必须产生三个不同且包含事件序号的工作区标识。
包含纯技术路径的改进范围与中文改进内容可以通过结构化语言校验。
